# 실험 저장 형식

Hydraulic Lab의 웹 화면과 Windows 앱이 공유하는 JSON codec이다. 아래 함수는 파일·사용자 저장소에 접근하지 않는 순수 함수이며, 화면과 데스크톱 계층이 이를 사용해 파일 선택·자동 저장·원문 복구를 처리한다. 이 문서는 저장 계약을 설명하며 실제 검증 결과와 배포 상태는 각 버전의 별도 기록을 따른다.

## 저장하는 것

`type: "hydraulic-lab-project"`, `schemaVersion: 1`, `modelVersion: "hydraulic-quasistatic-1"`을 사용한다. 루트에는 `state`와 `observation`이 있다.

- `state`: 모형 버전, 세 설정(`pumpFlowM3s`, `reliefPressurePa`, `resistingForceN`), 명령(`extend`, `neutral`, `retract`), 위치 `positionM`, 경과 시간 `timeS`, 양실 게이지압 `pressureAPa`·`pressureBPa`, 누적 에너지 `energyJ: {pump, load, relief}`, 누적 통과 체적 `cumulativeVolumeM3: {pump, relief}`.
- `observation`: 관찰 배율 `playbackRate`, 화면 선택 `view`, 수동 시점 `camera`.

상태는 SI 단위다. 설정뿐 아니라 경과 시간·격리 압력·누적량을 함께 보관하므로 중립 유지와 행정 끝 릴리프 상태를 다시 열어 이어 계산할 수 있다. 탱크·양실 체적, 순간 유량·동력 등 상태에서 도출하는 값은 중복 저장하지 않는다. 재생 여부와 시간 기준 시계, 날짜도 저장하지 않는다. 화면에서 파일을 열거나 자동 저장을 복원하면 일시정지 상태로 시작한다.

학습 안내의 단계·완료 여부·확인 수치는 현재 실행 세션의 보조 기록이며 실험 파일에 저장하지 않는다. 파일 열기·새 실험·앱 재시작은 안내를 종료하지만 저장된 물리 상태·보기·시점은 유지한다. 현재 세션의 직전 실험 되돌리기는 해당 안내 기록도 함께 복구한다.

`view`의 기본값은 다음과 같다.

```js
{
  mode: 'cutaway', explode: .35, labels: true, selectedPart: 'piston',
  layers: { housing: true, seals: true, paths: true },
  pressureColors: true, flowArrows: true
}
```

보기 방식은 `assembled`·`cutaway`·`exploded`, 분해 간격은 0..1이다. 부품 선택은 형상 모듈의 34개 부품 ID에 한정한다. 압력 색상과 유량 화살표는 별도 관찰 선택이며 모형의 압력·유량을 바꾸지 않는다. 관찰 배율은 .1..4, 기본값은 1이다. 배율을 바꿔도 이미 기록한 시간은 변하지 않으며, 재생 중 이후 전달할 시간 간격에 배율을 적용한다.

카메라는 `null` 또는 `{position: [x,y,z], target: [x,y,z], zoom?}`이다. 각 좌표는 유한한 −100..100m, 시점과 대상 사이 거리는 .20..4m, 확대는 .25..4다. 거리 경계에서 1e−10m의 산술 오차만 허용하고 입력 숫자를 바꾸지 않는다. `null`은 저장된 수동 시점이 없다는 뜻으로 화면에서 해당 관찰 상태의 기본 시점으로 복원한다. 확대 생략은 기본 확대를 뜻하며 codec은 생략 상태도 그대로 보존한다.

## 읽기와 보존

`parseProject(text)`는 전체 기록을 검증한 뒤 새 객체를 반환한다. 단일 UTF-8 BOM은 읽기에서만 건너뛰며, 원문 문자열은 바뀌지 않는다. BOM·공백을 포함한 UTF-8 크기 제한은 10 MiB다. 숫자 문자열·비유한 수치·누락·알 수 없는 키·지원 범위 밖의 값은 거부한다. JavaScript의 음수 0도 JSON 재직렬화 시 부호가 사라지므로 저장 수치로 받지 않는다. JSON의 각 계층을 엄격히 확인하므로 추가 값이 조용히 사라지지 않는다.

모형의 `assertValidState`와 동일한 SI 범위·압력·에너지·누적 체적 관계를 검사한다. 예를 들어 현재 명령과 양실 압력, `펌프 누적 체적 ≈ 펌프 유량 × 경과 시간`, `릴리프 에너지 ≈ 릴리프 압력 × 릴리프 누적 체적`, `펌프 에너지 ≈ 부하 에너지 + 릴리프 에너지`가 맞아야 한다. 설정 변경은 같은 위치의 새 실험으로 초기화하는 모형 계약이므로, 과거 누적량에 다른 설정을 끼워 넣지 않는다. 경과 시간은 모형과 같이 0..10⁹초다. 수치 허용 오차는 검증에만 쓰며 원래 값을 재계산하거나 덮어쓰지 않는다.

정상 기록은 `serializeProject`→`parseProject` 후 상태·관찰 값이 정확히 같다. 직렬화도 먼저 엄격히 검증하고 잘못된 상태를 보정하지 않는다. 속성 순서는 일정하며 같은 기록은 같은 JSON으로 저장한다.

오류는 `ProjectError`로 전달하고 `preserveOriginal: true`를 제공한다. 더 높은 스키마·동일 계열의 더 높은 모형 버전은 `FUTURE_SCHEMA`·`FUTURE_MODEL`, `futureVersion: true`로 구분한다. 파일 열기는 전체 검증이 성공한 뒤에만 현재 관찰을 교체한다. 손상되거나 더 새로운 버전의 자동 저장은 기존 키의 원문을 유지하고 자동 덮어쓰기를 중지한다. 원문 내려받기로 보호 중인 텍스트를 보관할 수 있으며, 그동안 진행한 현재 실험은 별도 파일로 저장한다.

## 새 관찰 만들기

`createProject({state, playbackRate, view, camera})`는 앱 내부에서 새 관찰을 만드는 함수다. 유효한 `state`는 숫자 그대로 복사한다. 무효한 내부 입력은 정상화한 설정과 범위 안의 위치를 이용해 **새 실험**을 만들며 명령·압력·경과 시간·누적량을 초기화한다. 압력이나 누적 에너지를 각각 잘라내어 존재하지 않는 계산 이력을 만들지 않는다. 파일을 읽을 때는 이 함수를 대체 검증기로 사용하지 않고 반드시 `parseProject`를 사용한다.

`normalizeView`와 `normalizePlaybackRate`도 내부 조작값을 위한 정상화 함수다. 어떤 함수도 전달받은 상태·화면·좌표 배열을 변경하지 않는다.

## 순수 검사

`node --test tests/project.test.mjs`로 저장 검사를 실행한다. 이동·중립·압력 제한·부분 프레임 행정 끝·설정 초기화·무부하의 실제 모형 상태를 왕복 저장하고, 복원 전후에 같은 다음 시간 간격을 진행했을 때 반환값 전체가 같은지 확인한다. 수치·물리 관계·버전·키·BOM·UTF-8 크기·카메라 경계를 함께 검사한다. 파일 선택·자동 저장·앱 재실행은 별도의 브라우저·데스크톱 검사에서 합성 파일과 격리 프로필로 다룬다. 실제 사용자 파일이나 사용 중인 프로필을 검사 데이터로 사용하지 않는다.
